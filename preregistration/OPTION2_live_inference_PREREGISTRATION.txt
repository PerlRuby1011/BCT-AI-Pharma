======================================================================
1. WHY THIS EXPERIMENT EXISTS
======================================================================

The present evaluation cannot answer RQ1 ("counterfeit detection above
90%"), and the manuscript already says so (Section 7, RQ1 answer;
Section 5.8). The reason is structural:

  evaluation/run_simulation.py:159-162
      cnn_authenticity = clip(1.0 - 0.30*severity_norm + N(0, 0.06))
      isolation_score  = clip(N(0.38, 0.13))
      custody_trust    = clip(1.0 - 0.90*severity_norm + N(0, 0.05))

No trained model is invoked anywhere in run_single_simulation_run(). The
reported detection rate is a function of the PTS aggregation applied to
closed-form severity proxies. It therefore has ZERO functional dependence
on CNN accuracy, Isolation Forest accuracy, or LSTM accuracy. Improving a
model cannot change it; degrading a model cannot change it. The ablation
table in the experiment report demonstrates this directly: Phases 3-5
improve the individual AI modules and move the detection column by exactly
0.00 pp.

The purpose of this redesign is to make system-level detection causally
depend on model quality. That is the entire objective. A higher number is
NOT the objective, and section 7 below fixes the reporting obligations
that follow from saying so.

======================================================================
2. HYPOTHESIS, AND WHAT WOULD FALSIFY IT
======================================================================

H1 (causal coupling). Under the redesign, system-level counterfeit
    detection rate becomes sensitive to CNN classification accuracy.
    Operationalized: deliberately degrading the CNN (by raising
    cnn.overlap_factor from 0.10 to 0.30) produces a detection-rate change
    of magnitude > 1.0 pp, versus the 0.00 pp the current design produces.
    FALSIFIED IF: the degraded-CNN arm moves detection by < 1.0 pp. That
    outcome would mean the redesign failed at its stated purpose, and it
    must be reported as a failed redesign, not quietly discarded.

H2 (no directional prediction). The redesign's effect on the absolute
    detection rate is NOT predicted. It may land above or below 71.4%.
    Both outcomes are scientifically informative and both will be
    reported. See section 7.

H3 (provenance carries signal only when counterfeiting is
    source-concentrated). ADDED 2026-07-28 alongside the 3.1 amendment.
    Under history-based reputation, blockchain provenance can only
    discriminate if counterfeits concentrate in identifiable
    organizations. When counterfeits are injected uniformly at random
    across the network, no organization accumulates a disproportionate
    prior record, every trust score converges to the same value, and S1
    carries no label information.
    Operationalized: the BCT-AI advantage over AI-Only is larger under
    clustered counterfeit injection (cluster_counterfeit_by_manufacturer
    = true) than under uniform injection, by a margin > 1.0 pp.
    FALSIFIED IF: the advantage is equal or smaller under clustering.

    This prediction is registered BEFORE the arms are run, and it is
    consequential either way. If confirmed, it says something the
    conference version does not: blockchain provenance contributes to
    counterfeit detection precisely when counterfeiting is
    source-concentrated, which is the empirically documented pattern
    (Mackey and Nayyar attribute 67% of incidents to the wholesale
    distributor level, cited in Section 2.1 of the manuscript). If
    falsified, the honest conclusion is that provenance as modelled here
    adds nothing, and the manuscript must say so.

Note explicitly: H1 is the hypothesis this experiment exists to test.
"Detection exceeds 90%" is NOT a hypothesis of this experiment, is not a
success criterion, and does not appear in any decision rule below.

3. PROTOCOL — SIGNAL CONSTRUCTION
======================================================================

For every anomaly-labelled transaction (12,075 per seed: 2,300
counterfeit-labelled plus the other four anomaly classes), three PTS
inputs are constructed as follows. All three replace closed-form proxies
with quantities derived from data or from a trained model.

3.1 PROVENANCE S1 — derived from the actual custody chain
    CURRENT:  clip(1.0 - 0.90*severity_norm + N(0, 0.05))

    AMENDED 2026-07-28. The original wording specified organization trust
    "assigned once per seed from its org_type, independent of any anomaly
    label." That specification is now WITHDRAWN. Under it, S1 depends only
    on which organizations handled a product and how many, so S1 is
    statistically independent of counterfeit status by construction. The
    BCT-AI condition would then combine a signal term (S8) with a term
    carrying no label information, while AI-Only uses S8 alone. Adding a
    label-independent term to a discriminative score dilutes it, so that
    specification would have made BCT-AI <= AI-Only close to inevitable —
    the mirror image of the rigging risk in section 5, biased against the
    thesis rather than for it. Neither direction is acceptable: the
    experiment must be capable of returning either answer.

    REPLACE WITH — history-based reputation, temporally causal:
    Group the transaction table by product_id and order by timestamp to
    obtain the realized custody chain. Each organization's trust score is
    derived from counterfeits attributed to that organization in PRIOR
    periods only:

      - the timeline is split at its midpoint;
      - an organization's counterfeit rate is estimated on the first half
        (the burn-in period) using only transactions where it appears as
        from_org;
      - trust = 1 - penalty * (that organization's normalized prior
        counterfeit rate);
      - detection metrics are computed ONLY on second-half transactions,
        so no organization's trust is ever informed by the row being
        scored, nor by any contemporaneous or future row.

    S1 is the product of trust scores along the realized chain, exactly as
    score_provenance_integrity() already specifies.

    WHY THIS IS NOT CIRCULAR. Trust never reads the label of the row being
    scored. It reads confirmed history, which is precisely what a
    provenance ledger provides and what real supplier-reputation systems
    use. The lag between an incident and its attribution is a property of
    the real system, not an artifact introduced here. An organization with
    a clean prior record contributes no penalty regardless of what the
    current row turns out to be.

    THE PENALTY CONSTANT is fixed before the run from the feasibility
    spike, chosen so that mean S1 across all products stays high enough
    that S1 alone does not push every product below the alert threshold
    (see the degeneracy check in section 6, R8). It is not tuned against
    any detection rate.

    NORMALIZATION — fixed 2026-07-28 from spike measurement. An
    organization is penalized only for the EXCESS of its prior counterfeit
    rate over the network base rate:

        trust = 1 - penalty * clip((org_rate - base_rate)/base_rate, 0, 3.0)

    An organization no worse than baseline carries NO penalty. The spike
    first tested normalization by the maximum observed rate
    (rate / rate.max()); that formulation fails R8, because under uniform
    injection every organization has a near-identical rate, the ratio is
    ~1 for all of them, and the penalty compounds over ~12 handoffs into a
    uniformly low S1 that pushes every product below the alert line
    regardless of severity. Measured: mean S1 fell to 0.407 (penalty 0.15)
    and 0.162 (penalty 0.30) under uniform injection. The excess-over-base
    formulation holds mean S1 at 0.976 (penalty 0.10) under uniform
    injection while preserving separation under clustering.

    PENALTY CONSTANT = 0.10, FROZEN. This is the only value tested that
    satisfies R8 under BOTH injection modes:
        penalty 0.10  uniform  PTS(clean)=0.897  clustered PTS(clean)=0.802  PASS/PASS
        penalty 0.20  uniform  PTS(clean)=0.881  clustered PTS(clean)=0.707  PASS/FAIL
        penalty 0.30+ clustered PTS(clean) <= 0.627, and at 0.40+ the
                      compromised organizations saturate the cap, driving
                      S1(counterfeit) to 0.000
    It was selected against the R8 degeneracy criterion alone. No
    detection rate was computed at any penalty value.

    THIS IS THE MOST IMPORTANT ITEM IN THE PROTOCOL. See section 5.

3.2 CNN AUTHENTICITY — live forward pass
    CURRENT:  clip(1.0 - 0.30*severity_norm + N(0, 0.06))
    REPLACE WITH: generate one packaging feature tensor per transaction
    using generate_synthetic_packaging_images()'s existing class
    signatures, with the class assigned by anomaly_type:
        counterfeit_product  -> drawn from the tamper classes
                                (Hologram Mismatch / Printing Defects)
        tampered_package     -> Seal Broken / Package Resealed
        all other rows       -> Authentic
    Severity modulates the blend fraction toward the authentic signature,
    so a low-severity counterfeit is genuinely harder to classify. The
    tensor is then scored by the TRAINED CNN, and cnn_authenticity_score
    is taken as the model's predicted probability of the Authentic class.

3.3 ISOLATION FOREST ANOMALY SCORE — live inference
    CURRENT:  clip(N(0.38, 0.13))  [constant; not even severity-linked]
    REPLACE WITH: generate a cold-chain reading sequence per transaction
    via _generate_normal_readings(), apply _apply_anomaly() for rows
    labelled temperature_excursion, and score through the TRAINED
    Isolation Forest using normalized_anomaly_scores() with the existing
    fixed calibration bounds from calibrate_score_normalization(). The
    per-transaction score is the mean normalized score over the sequence.

3.4 UNCHANGED — frozen for comparability
    - Anomaly injection: untouched. Same counts, same severity
      distribution U[0.4, 1.0], same clustering behaviour.
    - Transaction generation: untouched.
    - PTS weights and formula: untouched, at published baseline values.
    - Alert threshold 0.75 and quarantine threshold 0.50: untouched.
      NO THRESHOLD IS TO BE ADJUSTED IN THIS EXPERIMENT FOR ANY REASON.
    - Seeds 42-51, ten of them, all reported.
    - Model training protocol and hyperparameters: as published.

4. PROTOCOL — ARMS AND EXECUTION ORDER
======================================================================

Exactly four arms, run in this order, each over seeds 42-51:

  ARM 0  Proxy baseline (current design)         — reproduces 71.4%,
                                                    confirms harness parity
  ARM 1  Live inference, published CNN
         (cnn.overlap_factor = 0.10),
         UNIFORM counterfeit injection           — primary result
  ARM 2  Live inference, degraded CNN
         (cnn.overlap_factor = 0.30)             — H1 test
  ARM 3  Live inference, degraded Isolation
         Forest (contamination 0.05 -> 0.20)     — H1 test, second module
  ARM 4  Live inference, published CNN,
         CLUSTERED counterfeit injection
         (cluster_counterfeit_by_manufacturer
          = true)                                — H3 test
         ADDED 2026-07-28 with H3. Differs from ARM 1 in the injection
         mode ONLY; identical models, weights, thresholds and seeds. H3
         is judged on (ARM 4 BCT-AI advantage) - (ARM 1 BCT-AI advantage).

Model reuse across arms, fixed now: ARMs 1, 3 and 4 share one CNN trained
at overlap_factor 0.10; ARM 2 uses a separately trained CNN at 0.30. ARMs
1, 2 and 4 share one Isolation Forest at contamination 0.05; ARM 3 uses a
separately trained forest at 0.20. No model is trained more than once and
none is reselected after any metric is seen.

Models are trained ONCE per arm configuration, before any detection
metric is computed, and are not retrained or reselected afterwards.

The experiment runs ONE TIME. If a genuine implementation bug is
discovered after results are seen, the fix and the re-run are both
recorded in CHANGES.md with the reason, and the discarded result is
reported alongside the corrected one rather than replaced by it.

======================================================================
5. THE CENTRAL METHODOLOGICAL RISK
======================================================================

If 3.2 and 3.3 are implemented but 3.1 is NOT — that is, if the CNN and
Isolation Forest become live while provenance remains the severity-linked
proxy — then the BCT-AI condition keeps a hand-tuned proxy signal with a
0.90 severity slope while the AI-Only condition is forced onto live model
output. The comparison would then be rigged in favour of the paper's own
thesis, and the resulting BCT-AI advantage would be an artifact of the
asymmetry rather than evidence of anything.

This would be WORSE than the current design, which at least applies the
same proxy treatment to both conditions and is documented as doing so.

Accordingly: 3.1 IS NOT OPTIONAL. If deriving provenance from realized
custody chains proves infeasible, the correct action is to abandon the
redesign and leave the paper as written — NOT to ship 3.2 and 3.3 alone.
This is the single most likely way for this experiment to produce a
result that looks good and means nothing.

A secondary asymmetry check: the AI-Only condition must consume exactly
the same live CNN and Isolation Forest outputs as BCT-AI, differing only
in PTS weighting (all weight on ai_confidence), as it does today.

6. PRE-REGISTERED DECISION RULES
======================================================================

Fixed now, before any result is seen:

R1. ARM 0 must reproduce 71.4% +/- 1.4% within Monte Carlo error. If it
    does not, the harness has drifted and NOTHING ELSE IS INTERPRETED
    until that is explained.

R2. H1 is judged solely on |ARM 1 - ARM 2| and |ARM 1 - ARM 3|, against
    the 1.0 pp threshold set in section 2. This judgement does not
    depend on the absolute value of ARM 1.

R3. ARM 1's detection rate is reported as the new measured value
    whatever it is. If it is below 71.4%, that is the finding and it is
    reported as such, in the abstract if the abstract carries a detection
    number at all.

R4. If ARM 1 exceeds 90%, RQ1 may be revisited — but ONLY if R1 passed
    and H1 was confirmed. A high number from a redesign that failed its
    own coupling test is not evidence about RQ1 and will not be used as
    such.

R5. No parameter outside the four arms specified in section 4 is to be
    varied. If a result is disappointing, the protocol does not permit
    "trying something else" and reporting the better outcome. The
    permitted response to a disappointing result is to report it.

R6. Both the proxy and live-inference results remain in the manuscript.
    The live-inference experiment is reported as a NEW experiment in its
    own subsection, not as a revision of Table VI or of any published
    number. The conference-version comparison stays as it is.

R7. DEGENERACY GATE (added 2026-07-28). Risk R-B was previously recorded
    only as something to "check and mention." It is now a gating rule,
    because the failure it describes produces a HIGH detection number that
    also PASSES H1, and would otherwise flow through R4 into a revisited
    RQ1 claim.

    The mechanism: the synthetic packaging generator yields weighted
    F1 = 1.000 at overlap_factor 0.10 (Section 5.4 of the manuscript). A
    classifier that is effectively perfect on its own synthetic signatures
    returns P(Authentic) collapsed onto {0, 1}. Detection then becomes a
    near-deterministic function of the tamper class ASSIGNED from
    anomaly_type in 3.2 — i.e. a proxy reached by a longer route, now
    measuring "was the tensor labelled correctly" rather than any
    detection capability. Degrading the CNN still moves that number, so
    H1 confirms and the failure is invisible to every other rule.

    THE GATE. Before any arm's detection rate is interpreted, the
    distribution of P(Authentic) returned on severity-blended counterfeit
    tensors is inspected. Define degenerate mass as the fraction of
    predictions below 0.05 or above 0.95. If degenerate mass exceeds 90%,
    then:
      - ARM 1's detection rate supports NO claim about RQ1 at any value,
        including a value above 90%;
      - the redesign is reported as having reintroduced a proxy by a
        longer route, and said so in those words;
      - R4 is void for this run.
    A secondary requirement: corr(P(Authentic), severity) must be
    materially negative. If severity does not move the classifier's
    output, the severity-blend in 3.2 is not functioning and the same
    consequences apply.

    Both quantities are measured in the feasibility spike BEFORE the arms
    are run, so that this gate is evaluated on a known distribution rather
    than discovered afterwards.

R8. PROVENANCE DEGENERACY GATE (added 2026-07-28). The mirror failure on
    the S1 side: if the penalty constant or chain length drives mean S1 so
    low that PTS falls below the alert threshold for essentially every
    product regardless of severity, detection saturates near 100% and is
    again meaningless. Before the arms are run, the spike reports mean S1
    and the implied PTS at a neutral S8. The penalty constant is chosen so
    that this does not occur. If no penalty value satisfies both R8 and a
    non-zero H3 effect, the redesign is abandoned under section 5's
    abort clause.

8. EFFORT AND COMPUTE ESTIMATE
======================================================================

CORRECTION TO THE EXISTING ESTIMATE. The manuscript's Future Work item 1
states "an estimated order-of-magnitude increase in computational
budget", and the earlier handoff estimated "~10x current compute". Both
appear too pessimistic. The 28-minute figure for the six-phase
orchestrator run is dominated by MODEL TRAINING repeated six times; the
detection metric itself is cheap — all ten seeds at full 230,000-
transaction scale re-run in ~12 seconds.

Live inference does not require retraining per seed. Per seed it requires
inference over 12,075 anomaly-labelled rows; over ten seeds and four
arms, roughly 483,000 CNN forward passes and the same number of Isolation
Forest scorings.

  Isolation Forest scoring:  negligible (vectorized, ~seconds total)
  CNN forward passes:        the real cost. At 64x64 input this is
                             minutes-to-tens-of-minutes per arm on CPU,
                             faster on MPS. MUST BE MEASURED with a
                             timing probe on 1,000 rows before committing
                             — I am not willing to state a figure I have
                             not measured.
  Model training:            4 arms x one training pass each, comparable
                             to a single existing phase (~4-5 min each).

  TWO CONCRETE ENGINEERING CONSTRAINTS, both found by calculation:

  (a) MEMORY. Holding one 64x64x3 float32 tensor per anomaly row is
      12,075 x 49,152 bytes = 594 MB per seed, and ~5.9 GB if all ten
      seeds are materialized at once. Generation and scoring MUST be
      streamed in batches. Naive implementation will exhaust memory.
  (b) DETERMINISM. Each transaction's feature tensor must be generated
      from a seed derived deterministically from its transaction_id, so
      that the experiment is reproducible and so that batching order
      cannot change any result.

  ESTIMATED IMPLEMENTATION EFFORT: 4-8 hours, dominated by 3.1 (custody
  chain reconstruction) and by the streaming/determinism requirements
  above — not by compute. Plus a timing probe before commitment.

  The manuscript's Future Work text should be corrected to reflect this
  if the redesign is NOT undertaken, since it currently overstates the
  barrier to its own highest-priority follow-up.

9. RISKS
======================================================================

R-A  Asymmetric implementation (section 5). Mitigation: 3.1 is mandatory;
     abandon rather than ship partial.
R-B  The synthetic packaging generator is documented as degenerate
     (weighted F1 = 1.000 at overlap_factor 0.10, Section 5.4). A CNN
     that is nearly perfect on its own synthetic data will return
     near-binary authenticity probabilities, which may make detection a
     near-deterministic function of the assigned class and reintroduce a
     proxy by a longer route. This is a genuine threat to the redesign's
     validity and must be checked by inspecting the distribution of
     returned probabilities BEFORE interpreting any detection rate. If
     the probabilities are near-degenerate, say so in the write-up.
R-C  Custody chains may be short or singleton for many product_ids at
     230,000 transactions, weakening S1. Check the realized chain-length
     distribution before interpreting results.
R-D  Outcome below 71.4%. Not a risk to be mitigated — a possible
     finding, pre-accepted under R3.

12. DEVIATIONS FROM THE FROZEN PROTOCOL
======================================================================

D-1  Logging defect, fixed before the single run. The arm summary line
     used `value or fallback`, which silently replaces a legitimate 0.0
     (falsy in Python) with the fallback; it printed "advantage=+nan pp"
     when the true advantage was exactly 0.00. Display only — no stored
     value was affected. Replaced with explicit None checks.

D-2  ARM 0b added (published proxy design restricted to the evaluation
     half). The burn-in split means live arms see ~50% of the data, so
     ARM 1 vs ARM 0 would confound the redesign with sample restriction.
     ARM 0b is the matched control. This ADDS a comparison; it removes
     nothing and changes no frozen parameter.

D-3  Isolation Forest sequence length fixed at 20 readings per
     transaction. Protocol 3.3 did not specify a length. 20 was chosen
     for cost (the paper's standalone IF evaluation uses 60-reading
     episodes, but that measures a different quantity — a monitoring
     episode, not a single transaction's cold-chain context). Recorded
     rather than left implicit. No detection rate was consulted.

13. PRE-RUN PREDICTION — recorded BEFORE the single execution
======================================================================

Written 2026-07-28, after the plumbing smoke test but before the
pre-registered run. The smoke test is NOT informative about outcomes: its
CNN reached weighted F1 = 0.109 with mean P(Authentic) = 0.2054, i.e.
1/5 — uniform output over five classes, an untrained model. Its numbers
are discarded. What follows is arithmetic from the FROZEN constants plus
the spike's measured distributions, not from any smoke-test result.

For Class A (w1 = 0.25, w8 = 0.10; all classes are provenance-weighted
at least 2.5:1), BCT-AI fires when

    (0.25*S1 + 0.10*S8) / 0.35 < 0.75   =>   S8 < 2.625 - 2.5*S1

Under UNIFORM injection the spike measured S1 = 0.976, which requires
S8 < 0.185. With S8 = (P_authentic + (1 - isolation))/2 and isolation
~ 0.26, that requires P_authentic < -0.37 — unreachable. So:

  PREDICTION 1. ARM 1 BCT-AI detection will be at or near ZERO. Not low:
  structurally unable to fire. Provenance at ~0.98 pins PTS near 0.84
