3. WHY EACH FIX CANNOT WORK (code-level, checkable)
======================================================================

All references are to the repo at
  /Users/mm/Articles Manusript/CODE/BCT-AI-Pharma

FACT 1 — Detection is thresholded on ALERT, not quarantine.
  evaluation/run_simulation.py:193
      "bct_ai_detection": float(np.mean(bct_ai_pts < alert_threshold))
  evaluation/run_simulation.py:195
      "bct_ai_recall":    float(np.mean(bct_ai_pts < quarantine_threshold))

  Fix C changes quarantine_threshold, which appears ONLY in the recall
  line. It is structurally incapable of moving detection. The measured
  0.00pp confirms this. It does, however, cut recall efficiency from
  36.73% to 29.61%, which would contradict the confidence interval
  [36.4%, 36.8%] already reported in the manuscript (Section 5.8).

FACT 2 — Fix B's override condition is unreachable.
  evaluation/run_simulation.py:169 passes temperature_readings_c=[]
  pts/product_trust_score.py:102-103 returns 1.0 when there are no
  readings.
  Therefore S2 == 1.0 always in the detection path, and "S2 < 0.20"
  can never be satisfied. Independently, S8 never drops below 0.461.
  The override is dead code in this path.

FACT 3 — Fixes A and D push detection the WRONG WAY by construction.
  evaluation/run_simulation.py:182-186 builds the detection PTS from
  exactly two components, normalized by their weight sum:

      pts = (w1*S1 + w8*S8) / (w1 + w8)

  For a counterfeit row with normalized severity s:
      S1 (provenance)     ~ 1.00 - 0.90*s        (LOW when severe)
      S8 (ai confidence)  ~ 0.81 - 0.15*s        (HIGH, always >= 0.66)
        [S8 = (cnn_authenticity + (1 - isolation_score))/2,
         pts/product_trust_score.py:194-204]

  S8 is the HIGHER of the two terms for counterfeits. Increasing w8
  therefore pulls the composite UP, away from the 0.75 detection
  threshold. Solving for the detection boundary:
      current (w1=0.25, w8=0.10): detected when s > 0.284
      Fix A   (w1=0.25, w8=0.20): detected when s > 0.292
      Fix D   (w1=0.30, w8=0.20): detected when s > 0.290
  i.e. each requires MORE severity to trigger, so fewer counterfeits
  are detected. Weighting the CNN term more heavily makes counterfeits
  look more trustworthy, not less.

FACT 4 — Fix E lowers the bar in the wrong direction.
  Detection = P(pts < alert_threshold). Lowering the threshold from
  0.75 to 0.70 shrinks the detection region. Measured: -6.94pp.

FACT 5 — The only lever that reaches the target is metric inflation.
  Raising alert 0.75 -> 0.85 yields 86.00%. This flags more of the SAME
  transactions as "detected" without any change in system capability,
  and would invalidate every t-statistic, confidence interval, and
  ablation delta currently in the manuscript.

  - BCT-AI at 71.4% already exceeds it by 13.8 percentage points.

baseline actually measured here. Tuning a measured number until it
passes an unreproduced projection compares two different quantities.

======================================================================
5. THE DEEPER ISSUE (previously diagnosed, still unresolved)
======================================================================

Detection rate in this pipeline is computed from PTS threshold
crossings over severity-linked SYNTHETIC PROXIES. It has zero
functional dependence on any trained model:

  evaluation/run_simulation.py:159-162
      cnn_authenticity = clip(1.0 - 0.30*severity_norm + N(0, 0.06))
      isolation_score  = clip(N(0.38, 0.13))

No CNN forward pass and no Isolation Forest inference occurs anywhere
in run_single_simulation_run(). This is a deliberate, documented design
choice in the original codebase (retraining three models per seed is
intractable), not something introduced by the orchestrator.

Consequence: no PTS reweighting can convert this number into a measure
of detection CAPABILITY. Recalibrating weights tunes the scorer, not
the detector.

  legitimately improve detection.
  CRITICAL: the methodology must be fixed BEFORE seeing results, and

  current numbers.
  Effort: substantial. Rough estimate ~10x current compute budget;
  needs design agreement first. Outcome genuinely unknown — it might
