# Release 1.1.0: conference-reported reference values separated from computed results

Release 1.1.0, prepared 2–10 November 2026 (initial preparation and documentation-only passes; see `CHANGES.md`). Archived evidence package: version DOI 10.5281/zenodo.24097169 (concept DOI 10.5281/zenodo.21987357).

## Why

Up to release 1.0.x, conference-reported BCCA 2026 values were stored in `config.yaml` and passed into computed outputs:

- `evaluation/baseline_comparison.py` built a "Table VI baseline comparison" from the configured percentages (96.8 / 78.2 / 41.7 / 23.4%) instead of recomputing them from transaction-level predictions. `simulate_per_run_detection_rates` added Gaussian jitter around those values.
- The LSTM, CNN and Isolation Forest pipelines returned the configured `target_metrics` next to the computed `metrics`.
- The Monte Carlo results included the configured conference values (`paper_reference`) and `real_world_range`.
- The PTS calibration diagnostic compared each variant with a hard-coded 78.2% and wrote that value into its output.
- The results notebook plotted the configured values next to computed ones.

The approximately 71.4% detection reported by this repository is calculated separately, from transaction-level scores, with the implemented proxy-score decision rule. The configured values and the computed values are therefore not two measurements of the same evaluation.

## What changed

| Area | Change |
|---|---|
| Configuration | One labelled section, `bcca2026_reference_values`, holds all conference-reported values: the Table VI comparison (formerly `baseline_comparison`), `lstm_metrics` / `cnn_metrics` / `isolation_forest_metrics` (formerly `*.target_metrics`), `statistical_tests` (formerly `statistical_validation` t-values), and `monte_carlo` (formerly `monte_carlo` conference values and `real_world_range`). Input sections now hold inputs only (for `monte_carlo`, only `sensor_drift.perturbation_celsius`). |
| Historical code | `historical/bcca2026_reference.py` keeps the table builder and the jitter helper (same algorithm, checked by test) plus tagged getters for the other conference values. Every return value carries a provenance marker. |
| Current outputs | The component pipelines return `metrics` (and `quantization`) only. The Monte Carlo functions return computed values only. `run_full_pipeline` has no `baseline_comparison`, `improvement_ratios` or `relative_improvement`. The `statistical_validation` note no longer quotes the conference t-values. Recall localization carries `basis: calculated … not an observed time`. |
| Calibration diagnostic | Compares each variant with the AI-Only detection computed in the same runs. `ai_only_baseline_pct` is removed. Output goes to a new timestamped file if `results/pts_calibration_diagnostic.json` already exists, so archived outputs are never overwritten. |
| Notebook | Plots computed metrics only. The "paper target vs this run" comparisons and the Table VI bar charts are removed. |
| Runtime guard | `evaluation/result_guards.py`, called by `run_simulation.write_results`, `orchestrate.save_json`, `run_live_inference_experiment.py` and `pts/calibration_diagnostic.build_payload`. It detects the provenance marker (and copied reference-section keys). It does **not** detect an untagged bare number; that case is covered by the tests below. |
| Tests | `tests/test_reference_value_isolation.py` (static: no imports of `historical`, no reads of the reference section, no removed keys; config shape; guard behaviour). `tests/test_reference_outputs_stubbed.py` (output-level, stub models, no training: component pipelines, Monte Carlo, statistical validation, full pipeline including written JSON/CSV, calibration diagnostic). It checks both the marker and the reference numbers themselves. `tests/test_monte_carlo.py` and `tests/test_baseline_comparison.py` were updated. |

## What did not change

- No archived file under `results/` was modified. Archived outputs produced before 1.1.0 keep their `baseline_comparison`, `target_metrics`, `paper_reference`, `real_world_range` and `ai_only_baseline_pct` fields as historical records. Those fields hold conference-reported values, not computed results.
- No computed metric, model, checkpoint or experiment protocol changed.
- Earlier CHANGES.md entries and the `1.0.0` / `v1-reference` tags are unchanged. The existing Zenodo record is not modified; publishing would create a new version under the concept DOI.

## Remaining, out of scope for this release

- `blockchain.performance_targets`: the simulated network samples latency and success rate around conference Table III values (stipulated, not a deployed-network measurement; already stated in the README).
- `build_simulation_results_table` adds seeded jitter around single computed model metrics (CNN F1, LSTM MAPE/R², IF detection) to fill per-run columns. These are not reference values, but they are not independent per-run measurements either (the docstring says so).
